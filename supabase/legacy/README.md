# Legacy SQL files

Historical record. These files are **not** part of the migration pipeline anymore — they were applied ad-hoc to Supabase Studio before the project adopted the Supabase CLI on 2026-05-26.

The current schema state is captured in `../migrations/20260526090413_baseline.sql`, which was generated by `pg_dump`ing prod after all of these had been applied. The baseline is marked as already-applied on prod via `supabase migration repair --status applied 20260526090413`, so nothing here ever needs to run again.

**Do not** add new files here. New schema changes go through:

```
npm run db:new <name>   # creates supabase/migrations/<timestamp>_<name>.sql
# edit the file
supabase db push        # applies pending migrations to the linked project
npm run db:types        # regenerates lib/database.types.ts
```

The files here remain in git because the comments in each migration explain *why* a particular policy or column exists. When debugging a piece of behaviour, this folder is the change log.
